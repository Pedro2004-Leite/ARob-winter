## Lab handout - objectives and tasks

**Objective**: design, implement, and analyze several estimation solutions for the **roll and pitch angles** of the Parrot AR.Drone quadrotor, in simulation and experimentally.

**Deliverable**: single-column PDF report, max 15 pages, plus the `.m` scripts, submitted via Fenix using the official cover page (`25_26_UAVs_Lab_report_cover_page.docx`, already in this project). Questions are tagged **(T)** theoretical (to be solved before the lab session) or **(L)** laboratory (simulation/experiment, done during the session).

**Section 2 - Setup and experiments.** New devkit features vs. Lab 1:
- Entry script is now `start_here_NAV.m` (adds a 3rd top-level option: replay stored data).
- Wi-Fi control modes now log raw navigation data into a workspace variable `navdata` at **200 Hz**.
- The navdata-decoding block is an "extended version" exposing **accelerometer and rate-gyro** samples (Lab 1's devkit apparently only exposed velocity/attitude estimates, not raw IMU data).

Five data-collection experiments define the whole lab's empirical basis:
- **Experiment A**: sensors at rest, motors off, Hover mode, no take-off, ~30 s - baseline/quiescent noise characterization.
- **Experiment B**: on the ground, motors spinning, hull held down to prevent lift-off, take-off command sent, 30 s, then land - isolates motor-vibration-induced noise.
- **Experiment C**: real hover flight, take-off → 30 s hold → land - full operational noise (motor vibration + aerodynamic disturbance + control activity).
- **Experiment D**: step response in pitch reference, by editing `ARDroneHover.slx` (same style of step test as in Lab 1) - used to see filter behavior under a real, non-stationary attitude change.
- **Experiment E**: short waypoint mission - edit `ARDroneHover.slx` to give a 2-waypoint reference in `y`: origin → `[0,0,0.75]` → `[0,1,0.75]` → back to `[0,0,0.75]` → land, 5 s dwell between reference changes. Used to see estimator behavior across a realistic short mission.

**Section 3 - Modeling and characterization of sensors** (all "(L)"):
- 3.1-3.3: compute mean and covariance of accelerometer + rate-gyro readings for Experiments A, B, C respectively, and discuss *why* uncertainty grows from A→B→C (new disturbance sources: motor vibration in B, aerodynamic/control-induced disturbance in C).
- 3.4: compute "raw" pitch/roll from the accelerometer alone (the inclinometer formulas `φ̂_accel = atan2(...)`, `θ̂_accel = sin⁻¹(...)` documented in `lectures-22-23/notes/03-sensors-estimation.md`), to serve as the *baseline* against which every filter built later in the lab is compared.

**Section 4 - Kalman filters** (pitch first, then roll by symmetry in 4.7):
- 4.1: design/implement a **steady-state Kalman filter** for pitch using the pitch inclinometer measurement `θ_m` and rate-gyro measurement `w_ym` (note: MATLAB's `kalman()` or `estim()` commands are explicitly suggested - i.e. this is the LTI/steady-state KF machinery from `lectures-22-23/notes/02-control.md` Ch4, not a hand-rolled recursive filter).
- 4.2: derive, for the constant (steady-state) Kalman gains, the two closed-form transfer functions `θ_m → θ̂` and `w_ym → θ̂` - this is exactly the **complementary filter transfer-function pair** `G_L(s)`/`G_H(s)` documented in the lecture notes, just derived here from the KF gain rather than assumed a priori.
- 4.3: discuss effect of tuning `Q` (process noise weight) vs `R` (measurement noise weight) - same Bryson's-rule-style tradeoff as Ch4's LQR tuning discussion, applied here to the dual (estimation) problem.
- 4.4: **augment the state with a gyro-bias state** `b_y`, model `ḃ_y = 0` and `w_ym = q + b_y` (bias-augmented rate-gyro model). Suggested validation: inject an artificial bias in simulation and plot true vs. estimated bias to tune the filter. This is a **2-state, 2-output (or 2-state, single-channel with 2 measurement paths) special case** of exactly the same architecture as the full 6-state paper filter in Section 5, but restricted to a single axis (pitch, then roll) instead of jointly estimating a 3-vector attitude + 3-vector bias.
- 4.5: check whether the bias-free and bias-augmented filters are **complementary filters** in the formal sense (`G_L+G_H=1`), and discuss the tradeoffs of that filter class (fast high-frequency response from the gyro, but drift if not bias-compensated; slow but bias-free low-frequency truth from the inclinometer).
- 4.6: relate results back to Experiments A-E (i.e. show how filter performance/steady-state error changes with the noise regime of each experiment).
- 4.7: repeat everything for **roll**, using the roll inclinometer and rate-gyro measurement `w_xm` (by symmetry with pitch/`w_ym`).

**Section 5 - Integrated roll and pitch estimation** (the capstone task, "(L)" only, no separate theory sub-parts spelled out): implement the **Kalman filter for the "nominal system (2)"** of Batista/Silvestre/Oliveira (2011) - i.e. NOT the full nonlinear/GAS-error-dynamics observer from the paper's Theorem 3.4, but the simpler linear time-varying system (their Eq. 2) treated as a standard continuous-time Kalman filter (their Section 4, "Filter design"). The handout explicitly narrows scope: **only the accelerometer-based partial-attitude vector observation + 3-axis rate-gyro-bias estimation** is required, i.e. the exact 6-state filter of the paper (`x = [y; b_ω] ∈ R^6`), not a re-derivation of the observability proofs.

## Reference paper - Partial attitude and rate gyro bias estimation (Batista, Silvestre, Oliveira 2011)

**Problem**: with only a **single** body-fixed vector observation of a known constant inertial vector (e.g. gravity via the accelerometer), full attitude (`R ∈ SO(3)`) cannot be recovered - one rotational degree of freedom (rotation about the observed vector, i.e. yaw when the vector is gravity) is fundamentally unobservable, since `y(t) = Rᵀ(t) ᴵy = Rᵀ(t)R₀ᵀ ᴵy` for any rotation `R₀` about `ᴵy`. The paper's contribution: exploit **biased rate-gyro measurements** in addition to the single vector observation to (a) filter the vector observation itself, and (b) fully estimate the 3-axis gyro bias, with a filter that has **globally asymptotically stable (GAS)** error dynamics - stronger than typical EKF-based attitude filters, which only have local/linearization-based guarantees.

**System model** (their Eq. 1-2): let `y(t) ∈ R³` be the vector observation in body coordinates (`ᴵy = R(t)y(t)`, `ᴵy` constant, known, in the inertial frame), `ω_m(t) = ω(t) + b_ω(t)` the biased rate-gyro reading, `b_ω` the (assumed constant) bias. Using `ẏ = -S(ω)y` (differentiating the observation equation, since `Ṙ = RS(ω)`) and substituting the biased measurement:
```
ẋ₁(t) = -S(ω_m(t))x₁(t) + S(x₂(t))x₁(t)     [x₁ = y, using ω = ω_m - b_ω and x×y=-y×x]
ẋ₂(t) = 0                                    [x₂ = b_ω, constant]
y(t)  = x₁(t)
```
Compact linear time-varying (LTV) form - **this is the crux of the whole paper**: although the system is *physically* nonlinear (the state `x₂` multiplies `x₁` in the dynamics), it can be rewritten so that the *output* `y(t)` appears in the system matrix instead of the state, making it **linear time-varying for observer-design purposes** (the time-variation being driven by the measured/known signals `ω_m(t)` and `y(t)`, not by the unknown state):
```
ẋ(t) = A(t)x(t),  y(t) = Cx(t),   x = [x₁; x₂] ∈ R⁶
A(t) = [[-S(ω_m(t)), -S(y(t))], [0, 0]] ∈ R^{6×6},   C = [I, 0] ∈ R^{3×6}
```
This is the **"nominal system (2)"** the lab handout explicitly asks students to implement a Kalman filter for.

**Observability analysis** (Section 3, the paper's main theoretical contribution):
- Lemma 3.1: for a broader class of nonlinear systems expressible this way, observability of the underlying nonlinear system follows from invertibility of the **observability Gramian** of the associated LTV pair.
- Theorem 3.3: system (2) is observable on `[t₀,t_f]` iff for every unit vector `d ∈ R³`, there exists `t* ∈ [t₀,t_f]` with `‖y(t*)×d‖ > 0` - i.e., **the vector observation `y(t)` must not stay constant/parallel to any fixed direction throughout the interval** (the vehicle must actually rotate/maneuver relative to the observed vector). A vehicle sitting motionless in hover, with `y(t)` = constant gravity direction in body frame, would make this system **unobservable** - directly analogous to, and a strict generalization of, the course's own "rate-gyro-only → not observable" worked example in `lectures-22-23/notes/03-sensors-estimation.md` (there, a *constant-turn* roll estimator failed observability from yaw-rate alone; here, a *stationary* attitude/bias estimator fails observability from a single constant vector reading alone - both need an added, independent source of information/persistent excitation to become observable).
- Theorem 3.4 (stronger, needed for GAS filter design): **uniform complete observability** holds iff there exist `α,δ>0` such that for every unit `d` and every `t`, some `t* ∈ [t,t+δ]` gives `‖y(t*)×d‖ ≥ α` - a **persistency-of-excitation** condition (not just "eventually observable," but observable with a uniform margin on every sliding window of length `δ`). This is the condition that actually gets invoked to prove the Kalman filter below has GAS error dynamics (via Kalman & Bucy 1961 / Jazwinski 1970 general stability results for uniformly completely observable LTV Kalman filters).

**Filter design (Section 4)**: because (2) is treated as LTV (not nonlinear) for filtering purposes, the **standard continuous-time Kalman filter** applies directly, with additive process/measurement noise `w(t)`, `n(t)` (covariances `Ξ`, `Θ`):
```
x̂̇(t) = A(t)x̂(t) + K(t)[y(t) - Cx̂(t)]
Ṗ(t) = A(t)P(t) + P(t)A(t)ᵀ + Ξ - P(t)CᵀΘ⁻¹CP(t)      (Riccati differential equation)
K(t) = P(t)CᵀΘ⁻¹
```
Because `(A(t),C)` is uniformly completely observable (Theorem 3.4), the filter error dynamics are **globally asymptotically stable** - this is the paper's headline result, and it is the reason the course picked this filter as the "advanced" capstone estimator for Lab 2 rather than a generic EKF.

**Simulation results (Section 5)**: accelerometer (gravity vector) + biased rate gyro; injected bias `b_ω=[2,-3,1]ᵀ·π/180 rad/s`; sensor noise std 0.05 m/s² (accel) and 0.05°/s (gyro); `Ξ=diag(0.05I,0.01I)`, `Θ=0.05I`. Recovers roll and pitch (the two Euler angles obtainable from a single vector = gravity) with small residual error (~tenths of a degree) and converges the gyro-bias estimate within ~20 s.

**Experimental results (Section 6)**: validated against a precision motion rate table (Ideal Aerosmith 2103HT, 0.00025° resolution ground truth) with a low-cost MEMSENSE NANO IMU (accel std 0.008 m/s², gyro std 0.95°/s, 150 Hz) - i.e. sensor quality comparable to what the AR.Drone's onboard IMU is expected to have. Filter converges fast (<1 s) even from a zero-bias initial guess, and steady-state roll/pitch error stays within about ±0.5-1° despite the raw accelerometer-only measurement being noisy (~±1-2°) - a concrete, quantified demonstration of the filtering benefit that Lab 2's Sections 3-4 ask students to reproduce qualitatively on the AR.Drone.

**Important note for the lab report**: the paper's `x₂ = b_ω` is the *full 3-axis* gyro bias and `x₁ = y` is the (3-component) vector observation itself (not roll/pitch angles directly) - recovering roll and pitch from the filtered `x̂₁` requires the same `atan2`/`sin⁻¹` inversion documented in `lectures-22-23/notes/03-sensors-estimation.md`'s "sensor-model inversion" section, applied post-filter instead of pre-filter (i.e. filter the raw vector first, then convert to angles - this generally gives better results than converting to angles first and filtering the angles, since the vector-space dynamics are the ones that are exactly LTV/exploitable, while angle-space dynamics involve trig nonlinearities).

## Connections to lecture material

- **Raw pitch/roll from accelerometer (handout 3.4)** ↔ the exact inclinometer formulas `φ̂_accel = atan2(y_accel,y, y_accel,z)`-style, `θ̂_accel = sin⁻¹(y_accel,x/g)` derived in `lectures-22-23/notes/03-sensors-estimation.md` under "Sensor-model inversion," including the explicit caveat there that this approach fails during maneuvers (motivating everything that follows in both the lecture and the lab).
- **Steady-state KF for pitch (4.1-4.3)** ↔ directly the LTI Kalman filter machinery from `lectures-22-23/notes/02-control.md` (Ch4: `K=lqr(...)`-style tooling, duality with `L=place(...)`) and the continuous-discrete KF equations in `03-sensors-estimation.md` (`Ad=I+ATs+A²Ts²/2`, `P_{k+1}=AdPkAdᵀ+Ts²Q`), specialized here to MATLAB's built-in `kalman()`/`estim()` for the steady-state (algebraic Riccati) solution rather than a manually-coded recursive filter.
- **Bias-augmented KF (4.4)** ↔ the exact "second-order complementary filter" structure documented in `03-sensors-estimation.md` (`x=[φ,b_p]`, `u=p_m`, `y=φ_m`, giving `Φ̂(s)=G_L(s)Φ_m(s)+G_H(s)P_m(s)/s`) - the lab has students re-derive/re-tune this same structure for pitch and roll on real AR.Drone data.
- **Complementarity check (4.5)** ↔ `lectures-22-23/notes/03-sensors-estimation.md`'s explicit statement that "the complementary filter is a Kalman filter with fixed (non-adaptive) gain" - Section 4.5 of the lab is literally asking students to verify this equivalence (`G_L+G_H=1`) for their own designed filters.
- **Section 5's paper-based filter** ↔ generalizes the course's own three-stage worked example in `03-sensors-estimation.md` ("rate-gyro only → not observable," "+ accelerometer → observable"): the Batista/Silvestre/Oliveira filter is the natural full-3D, full-rigor version of that same idea - single vector observation (accelerometer/gravity) + biased rate gyro, formalized with a proper observability proof and a GAS convergence guarantee, instead of the course's simplified scalar/coordinated-turn special case.
- The **LQR ↔ Kalman filter duality** explicitly taught in Ch4/Ch6 (`K=R⁻¹BᵀP` vs `L=ΣCᵀN⁻¹`, dual Riccati equations) is exactly the mathematical machinery underlying the paper's Riccati equation `Ṗ=AP+PAᵀ+Ξ-PCᵀΘ⁻¹CP` and gain `K=PCᵀΘ⁻¹` - same structure, just continuous-time LTV instead of LTI.
- The **AR.Drone-specific note in `03-sensors-estimation.md`** that the AR.Drone has no GPS and instead uses sonar + downward-camera vision is corroborated here: `setupHover.m`/`setupWPTracking.m`'s explicit in-code warning that the onboard position estimate (integrated optical-flow velocity) is inaccurate is precisely why Lab 2 focuses only on attitude (roll/pitch) estimation from IMU data, not full position/velocity estimation.

## Open questions / unclear points

- The handout's Eq. numbering ("system (2)") refers to the *paper's* equation 2, not a lab-internal numbering - confirmed by cross-checking against the paper itself (its Eq. (2) is exactly the compact LTV form `ẋ=A(t)x`, `y=Cx` derived above).
- The handout does not specify numeric noise covariances (`Q`, `R` / `Ξ`, `Θ`) to use for the AR.Drone - students are expected to derive these from the Experiment A-C mean/covariance characterization in Section 3, unlike the reference paper which states its simulation/experimental covariances explicitly. Matching the AR.Drone's real IMU noise characteristics to the paper's simulated/experimental values (from a much higher-grade MEMSENSE IMU) is left entirely to the student.
- `decode_32bit.m`'s `mark=2` branch (`hex2dec(hex_value)-2^31`) is used for signed integers but the exact set of navdata fields that require each of the three `mark` modes (unsigned int / signed int / float) is not documented in the script itself - would need the Parrot AR.Drone SDK's navdata structure reference to map specific byte offsets to sensor channels.
- Which specific navdata fields (byte offsets into the `NDS` structure referenced in `decode_32bit.m`'s comment, e.g. accelerometer/gyro sample locations) are wired into the "extended version" navdata-decoding Simulink block is not visible from the `.m` files alone (the block internals are in the binary `ARBlocks.slx` / `ARDroneHover_V2.slx`, not inspected here) - would require opening these `.slx` files in Simulink to confirm exact scaling/units of the raw accelerometer and rate-gyro channels before Section 3's mean/covariance characterization can be done correctly.
- The paper's filter is explicitly noted (Remark 4) to not be truly "optimal" in a strict sense because of multiplicative noise (the `S(y(t))` and `S(ω_m(t))` terms depend on noisy measured/estimated signals, not clean known signals) - the lab handout does not ask students to address this caveat, but it's worth flagging if a report reviewer probes filter optimality claims.
